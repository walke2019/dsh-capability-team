# 开发指南

本文面向贡献者。协作、文件、安全与 Token 的权威规则见 [AGENTS.md](../AGENTS.md)。

## 开发与测试

使用 Node.js 22 或更高版本。项目采用 Node.js 内置 `node:test`，通过模拟 DSH 上下文、模型目录和确认对话框运行；自动化测试不会调用真实模型或搜索服务。

```sh
npm test          # 构建 client.js 后运行测试
npm run lint      # 语法与仓库一致性检查
npm run build     # 检查包闭包及发布文件
npm run build:client  # 重建客户端 bundle
```

工具 Schema 测试会检查已注册工具的 JSON Schema。模拟测试不等于外部服务的实测。

## 验证状态与已知限制

文档记录的基线为根目录 403 项 + omni-search 26 项 + global-memory 23 项测试通过、0 失败（`npm test` 运行全部三组）。单元测试模拟宿主 API，不替代桌面或浏览器交互验收。可选网关、语音和共享记忆需要用户提供端点与凭据，其可用性取决于实际环境。验收时应查看最新任务或 CI 结果，不应把基线误认为所有集成都已完成在线验证。

## 文件与上下文规则概要

- 源码应保持模块职责清晰；300 行起考虑拆分，硬上限 500 行；测试文件上限 800 行。
- 已超限文件只能缩短；不要直接编辑生成 bundle。
- 大文件先搜索标题或标识符，再分段读取；已有文件做局部编辑，不整体覆盖。
- 控制输出和报告长度；敏感信息不得进入提示词、日志、文档或测试夹具。

完整且可执行的文件、Token 与协作规范见 [AGENTS.md](../AGENTS.md)。

## 客户端构建

工作台源码位于 `client/`。运行 `npm run build:client` 按文件名顺序合并为发布用的 `client.js`。DSH 加载单一客户端文件；修改源码后重建，不要直接编辑生成 bundle。

## 发布文件清单

`package.json` 的 `files` 字段是发布清单的权威来源。内容包括插件入口模块（角色、配置、路由、权限、工作流、记忆、集成与任务控制）、`client.js` 及客户端源码、语言文件、角色/主题技能、README、许可文件、测试和夹具、构建/检查脚本及 `cordis.patch.yml`。发布前运行 `npm run build` 检查包闭包和文件集合。
